# AIS — Asset Integrity Systems

Самостоятельная версия лендинга на основе переданных исходников Figma Make и пакета первой встречи от **12.09.2026**. Доработка: **13.09.2026**.

## Что здесь изменилось

Содержание и последовательность презентации сохранены. Служебная React/Vite-сборка Figma заменена статической HTML/CSS/JavaScript-реализацией: для этой страницы нет обязательной серверной логики и не нужны внешние пакеты. Это **не исправленный React-проект**: это самостоятельный перенос его интерфейса и содержимого. Оригинал сохранён в `reference/`.

Не нужны Figma, npm registry, Google Fonts, внешние фотографии или CDN для сборки/просмотра. Системные шрифты без поставки файлов шрифтов. Чужие фоновые фотографии из исходного кода заменены типографикой и схемой подхода, чтобы не зависеть от внешнего источника и непроверенных прав на изображения. Логотип не перерисован.

## Быстрый запуск

Требуется Node.js **22+**. Основные команды не устанавливают зависимости:

```bash
npm run verify
npm run preview
```

Открыть `http://127.0.0.1:4173/`. Сервер слушает только локальный адрес. `Ctrl+C` останавливает его. Изменили текст/стили — выполните `npm run build`, обновите браузер. HMR отсутствует.

Публичный кандидат отдельно:

```bash
npm run build:public
npm run preview:public
```

Адрес: `http://127.0.0.1:4174/`. Оба варианта можно также открыть через `dist-*/index.html`; для проверки загрузки PDF предпочтителен локальный сервер. В поставке есть отдельные однофайловые HTML-превью.

## Две физически разные сборки

| Команда / каталог | Содержание | Публикация |
|---|---|---|
| `npm run build` → `dist-investor/` | Полная презентация, финансовые сценарии, условия участия, исходный PDF | Только в защищённой среде после настройки доступа |
| `npm run build:public` → `dist-public/` | Подход, услуги, задачи, команда, контактный раздел | Кандидат для открытого показа, требует согласования владельца |

Инвестиционные данные не просто спрятаны стилями: в публичном HTML их нет; PDF, исходники и финансовый JSON туда не копируются. Общий клиентский JS не содержит финансовых констант. Это проверяется тестами. Сами **исходники и весь репозиторий остаются приватными**, поскольку в них хранится полная модель содержимого и PDF.

**Ни один каталог сам по себе не имеет аутентификации.** Название `investor`, `noindex` и `robots.txt` не защищают данные. Если загрузить `dist-investor` на обычный публичный хостинг, содержимое станет доступно. См. `SECURITY.md`.

## Где редактировать

- `content/site.json`: тексты, услуги, команда, имя контактного лица, телефон и почта.
- `content/investor.json`: сценарии и плановые вводные из документа. Правки только после согласования новой редакции источника.
- `src/styles.css`: палитра, типографика и адаптивные сетки.
- `src/app.js`: мобильное меню, якоря, вкладки, диалог, печать.
- `scripts/render.mjs`: разметка разделов.
- `assets/ais-monogram.png`: утверждённый логотип, байт-в-байт исходный PNG. Это не вектор.
- `private-assets/ais-first-meeting-2026-09-12.pdf`: исходный PDF без изменений.

Телефон и email намеренно пустые. Личная почта из GitHub не подставлялась как контакт компании. При заполнении корректными данными появятся рабочие `tel:`/`mailto:`-ссылки. При пустых полях нет фиктивной отправки. Регистрация компании не утверждается как состоявшийся факт.

## Загрузка на GitHub

В текущей среде подготовки GitHub предоставлял только чтение. **Репозиторий не создан, коммит не отправлен, сайт не опубликован.**

Самостоятельная загрузка с вашего компьютера:

```bash
# GitHub CLI должен быть установлен и авторизован:
gh auth login --hostname github.com --web --scopes workflow

# Из каталога этого проекта:
bash scripts/push-private.sh BabyninAleks-Zi/ais-landing
```

Скрипт проверяет аккаунт, спрашивает `private`, запускает тесты, создаёт приватный репозиторий при отсутствии или проверяет приватность существующего. В пустой репозиторий делает первый коммит `main`; если там только README/служебные файлы — отправляет отдельную ветку и открывает PR. В другой существующий проект не загружается, force-push не использует, Pages не включает. Для создания коммита должны быть настроены ваши Git `user.name`/`user.email`.

При ручном создании: имя `ais-landing`, **Private**, лучше без README/лицензии/`.gitignore`. Скрипт также поддерживает репозиторий только с README. Альтернатива — GitHub Desktop или Codex на вашем Mac с авторизованным Git. Пароли/токены в чат и в файлы проекта не нужны.

Разрешение `workflow` запрашивается для загрузки файлов `.github/workflows`; оно не включает публикацию автоматически. При уже настроенной авторизации без этого разрешения используйте `gh auth refresh --hostname github.com --scopes workflow`.

Скрипт проверен синтаксически, но его сетевой сценарий не выполнялся: в среде сборки нет авторизованного GitHub CLI.

## GitHub Pages: только после отдельного решения

`check.yml` проверяет проект, но не публикует. `pages-public.yml`:

1. Запускается только вручную.
2. Требует repository variable `AIS_ALLOW_PUBLIC_DEPLOY=true`.
3. Требует подтверждения `confirm_public` при запуске.
4. Передаёт только `dist-public`, никогда `dist-investor`.

До этого согласуйте публичный вариант и контакты. Затем Settings → Pages → Source: GitHub Actions; установите переменную и запустите workflow. Это **публичный** сайт даже при приватном репозитории, кроме специальных корпоративных режимов доступа. Доступность Pages для private repo зависит от тарифа. Не переводите весь репозиторий в Public ради Pages: там инвесторский PDF и исходные финансовые данные.

Если GitHub Actions недоступен, обе готовые сборки не зависят от него. Для защищённой инвесторской версии используется отдельный хостинг с проверкой доступа до выдачи HTML, JS, PDF и других файлов.

## Проверки и границы

`npm test` — Node test runner, без внешних библиотек. Проверяются неизменность ключевых чисел, финансовые подписи, единая шкала, ссылки, разделение редакций, подлинность файлов, повторяемость сборки и локальный сервер. Отчёт — `docs/QA_RU.md`.

Браузерный набор: `tests/browser_check.py`. Для повторения нужен отдельный Python с Playwright и Chromium; это не зависимость самого сайта. Он проверяет автономные HTML-документы через `set_content`, а не опубликованный сайт. Полное тестирование после развёртывания и проверка Safari/Firefox не выполнены.

Источники и границы изменений: `docs/SOURCES_RU.md`. Новая верстка не является обновлением/аудитом финансовой модели.
